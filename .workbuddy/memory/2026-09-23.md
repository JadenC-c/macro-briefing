## 重要修复：export-pdf.ps1 的 Edge headless 参数失效

- **现象**：本次运行脚本报 `FAILED: PDF not created.`，`C:\temp\briefing.html` 已生成（89,336 bytes）但无 PDF 输出；Edge 进程退出码 0、无报错。
- **根因**：**新版 Microsoft Edge 已不支持旧的 `--headless` 参数配合 `--print-to-pdf`**（静默不产出文件）。需改用 `--headless=new`。
- **修复**：脚本内 `--headless` → `--headless=new`；同时加入 `Remove-Item $tempPdf`（避免旧 PDF 残留导致误判成功）、等待重试窗口由 10 秒延长至 20 秒。
- **验证**：手动测试 `--headless=new` 立即成功（Edge 输出 "1227473 bytes written to file"），脚本修复后一次通过。
- **注意**：这是继"BOM 编码问题""异步写入时序问题"之后该脚本的**第三个**已修复缺陷。若日后 PDF 再次不生成，优先检查 Edge 版本对 headless 参数的支持。

## 经验

- **外部命令的"静默失败"最危险**：Edge headless 参数失效时退出码为 0、无任何错误输出。凡是"命令成功但产物不存在"的情形，应第一时间怀疑工具本身的行为变化（版本升级），而非自己的调用逻辑。
- 生成 PDF 后应校验产物（`Get-Item` 大小 + 解析 `/Count` 确认页数），不要仅凭脚本的 "SUCCESS" 判断。
- `git push` 报错时先读错误原文分类：`502`/`CONNECT tunnel failed` = 代理不可用；`schannel ... missing close_notify` = TLS 被中断；两者都属于环境问题，重试与改配置均无效，应直接记录并等网络恢复。
